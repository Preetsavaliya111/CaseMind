# CaseMind complete audit and repair record

Audit date: 2026-09-25

## Executive result

The repository, running application, PostgreSQL schema, Qdrant service, and configured free-provider AI path were audited together. The reported Create Case, Edit Case, invitation, team, and validation problems were reproduced and repaired. The final automated suites and the live provider workflow pass.

## Inventory audited

- 21 routed frontend workspaces and public/authentication screens.
- 57 backend API paths containing 74 operations.
- Authentication, invitations, password recovery, optional MFA, and session invalidation.
- Nine normalized roles, permission checks, tenant scope, team/department scope, and customer-safe case serialization.
- Cases, assignment, comments, attachments, SLA, escalation, notifications, search, dashboards, analytics, Documents, Knowledge, Organizational Memory, and AI/RAG.
- PostgreSQL migrations through `f4201d8be76a` and Qdrant readiness.
- Shared dialogs, selects, dropdown menus, form controls, responsive layout, empty/loading/error states, and keyboard-accessible labels.

## Defects found and repaired

| Area | Finding | Repair | Status |
|---|---|---|---|
| Create Case | Narrow left-aligned form left most of the workspace empty | Rebuilt as a centered, responsive two-column workspace with a case-details panel and sticky submission summary | Fixed |
| Create Case | Client sent fake `usr_001` and `org_001` ownership values | Removed fake identifiers; reporter and organization now come only from the authenticated backend context | Fixed |
| Create Case | Whitespace could satisfy client length rules | Trim-aware validation now matches backend intent | Fixed |
| Create Case | API failures were not displayed in the form | Added a visible submission error panel and preserved form state for retry | Fixed |
| Validation | The destructive/error token was gray | Replaced it with an accessible red error color | Fixed |
| Validation | Invalid input, textarea, and select controls did not consistently show a red outline | Added shared `aria-invalid` red border and focus-ring styling | Fixed |
| Edit Case | Save was disabled without field-level explanation | Save now validates on action and shows specific red field messages | Fixed |
| Edit Case | Update failures could leave the dialog without actionable feedback | Added an in-dialog API error state | Fixed |
| Assignees | API returned all active users and exposed old labels such as `admin` | Endpoint now returns only active users with assigned-case access and uses normalized titles such as `Organization Admin` | Fixed |
| Assignees | PostgreSQL failed on `DISTINCT users.*` because User contains JSON columns | Replaced the query with a distinct eligible-ID subquery, compatible with PostgreSQL and SQLite | Fixed |
| Assignees | An administrator-only organization looked like a broken list | Added clear guidance that a Support Agent must be invited and accept the invitation; no fictional users are created | Fixed |
| Authorization | Case pages requested `/cases/assignees` even for users without assignment permission | The query is now disabled unless the signed-in user has assign/reassign permission | Fixed |
| Dialogs | Fade animation overwrote transform-based centering | Removed transform-conflicting animation from dialog content | Fixed |
| Popups | The same animation could displace Radix select/dropdown content | Removed it from positioned select and dropdown surfaces | Fixed |
| Dialogs | Tall content could place actions outside the visible viewport | Shared dialog content is centered, viewport-bounded, and vertically scrollable | Fixed |
| Knowledge | Save Draft was silently disabled for invalid content | Added explicit labels, required markers, red field borders, and per-field messages | Fixed |
| Memory | One generic error did not identify invalid fields | Required title, summary, issue pattern, and evidence source now receive red invalid styling | Fixed |
| Invitations | Invalid name/email fields had no red outline | Added required markers and field-specific invalid styling while keeping the actionable error panel | Fixed |
| Teams | Missing department was not visually identified | Added required markers and invalid select styling | Fixed |
| Registration | Validation messages did not mark their controls | Connected all required fields to shared invalid styling | Fixed |
| Escalation | The action was silently disabled for a short reason | Action now validates on click, identifies the field, and displays backend failure details | Fixed |
